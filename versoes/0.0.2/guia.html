Visão geral

Arquitetura em quatro camadas

As interfaces apresentam os fluxos; JavaScript integra o navegador à API; Flask executa as regras de negócio; o banco persiste contas, giros e cupons. Há versões históricas e uma aplicação legada na raiz, então confira sempre o caminho do arquivo antes de alterar.

Interface · HTML/CSSEstrutura e apresentação da página principal e do painel MVP.
Cliente · JavaScriptEventos de formulário, chamadas HTTP, mensagens e animação da roleta.
API · Flask/PythonValidação, sessão, autenticação, regras de fidelidade e administração.
Persistência · PostgreSQLBanco Neon usado pelo backend da versão principal 0.0.2.
Tutoriais guiados

Como uma ação percorre o projeto

1. Cadastro, confirmação e login

A pessoa preenche o formulário

versoes/0.0.2/index.html define os campos. O atributo name é a chave que acompanha cada valor enviado.

O JavaScript prepara o envio

login.js lê os campos, transforma-os em dados JSON e envia POST /api/auth/register. preventDefault() impede o recarregamento normal da página.

O Python confere antes de guardar

mvp-tattoo/app.py valida nome, telefone, CPF, e-mail e tamanho da senha. Se algo estiver errado, devolve uma mensagem e não conclui o cadastro.

O banco guarda dados protegidos

A senha é transformada em hash; o CPF é representado por um HMAC. O servidor envia um e-mail de confirmação. A pessoa confirma pelo link para liberar o primeiro giro.

O login cria uma sessão

O servidor confere a senha com o hash guardado. Se estiver correta e o e-mail confirmado, cria uma sessão para reconhecer a pessoa nas próximas ações.

HTML → login.js → rota Flask → PostgreSQL → resposta para a página

2. Recuperar senha

Pedir o link

esqueci-senha.html envia o e-mail para POST /api/auth/password-reset.

Abrir a mensagem de e-mail

O servidor cria um token temporário e envia um endereço para redefinir a senha. O token expira e não é guardado em texto puro.

Escolher a senha nova

A mesma página identifica ?token=..., mostra o segundo formulário e envia a senha nova a POST /api/auth/reset-password.

esqueci-senha.html → login.js → duas rotas no app.py → banco

3. Girar a roleta

O clique pede uma rodada

script.js envia POST /api/spins/roll. O servidor exige que a pessoa esteja autenticada e tenha uma rodada pendente.

O servidor escolhe e registra o prêmio

O backend calcula o prêmio, marca a rodada como usada e cria o cupom. A página não escolhe o desconto.

A animação mostra a resposta

O JavaScript lê o segmento retornado pelo servidor, gira a roda e mostra o nome e o percentual do prêmio.

Clique → script.js → servidor escolhe/guarda → navegador anima o resultado

4. Acompanhar fidelidade e pedidos

O painel MVP é outra interface. Seu HTML fica em mvp-tattoo/public/index.html; seu JavaScript em public/app.js; suas rotas são atendidas pelo Flask. Ele reúne login, roleta, progresso, pedidos de tatuagem e ferramentas administrativas. Na versão principal 0.0.2, o caminho da página é /mvp.

5. Rodar e publicar

  • Para desenvolvimento local da versão principal, use as instruções de versoes/0.0.2/README.md.
  • O Flask serve tanto o site principal quanto APIs e painel. O arquivo server.js é apenas um iniciador alternativo do backend Python.
  • GitHub Pages serve arquivos estáticos, mas não executa Flask nem conecta o backend privado ao banco. Para a aplicação completa, hospede o backend e configure suas variáveis secretas.
  • A versão principal 0.0.2 usa o mesmo PostgreSQL/Neon e os dados que já eram usados pela 0.0.11. O banco SQLite da aplicação antiga na raiz é separado.
Leitura técnica

Contratos entre camadas

  • Formulários e API: os atributos name precisam corresponder às chaves consumidas pelas rotas Flask. login.js serializa os campos e trata respostas HTTP.
  • Rotas e persistência: o backend usa parâmetros SQL separados (%s) e transações para gravar estados como giro usado e cupom emitido.
  • Autenticação: a sessão identifica o cliente; decorators protegem rotas de cliente e de administração. Confirmação e recuperação usam tokens com expiração.
  • Prêmio da roleta: seleção e gravação são responsabilidade do servidor; script.js apenas converte o segmento retornado em animação e mensagem.
Segurança e privacidade

Arquivos que não devem ser compartilhados

  • .env: arquivo local de segredos, como conexão de banco, chaves e senhas. O tutorial explica para que serve, mas não lê nem mostra seu conteúdo. Nunca envie para o GitHub ou cole em uma conversa.
  • data.sqlite: banco antigo com registros; não publique nem apague sem plano de migração e backup.
  • uploads/: arquivos enviados por pessoas podem conter dados privados.
  • Senhas e connection strings: se já foram expostas, troque/rotacione pelo serviço correspondente.
  • .gitignore: lista arquivos locais que o Git não deve enviar. Ainda assim, sempre verifique o que será publicado.

Esta edição não copia código de credenciais, banco de clientes, uploads, nem o arquivo compactado original. A árvore lista o propósito dos componentes, sem exibir valores secretos ou dados pessoais.

Se algo não funcionar

Diagnóstico por camada

  1. A página está sem estilo? Confira se o href do CSS aponta para um arquivo que existe e se a grafia/capitalização está certa.
  2. O botão não faz nada? Confira o nome da função no HTML, o carregamento do JS, o id do elemento e o Console do navegador.
  3. Recebeu erro ao enviar? Confira a aba Network (Rede): URL, método, código HTTP e mensagem JSON do servidor.
  4. Cadastro não chega ao banco? Compare os name dos campos com as chaves que a rota Python lê e verifique a mensagem no terminal do backend.
  5. E-mail não chegou? A configuração SMTP precisa existir no ambiente do servidor; confira spam e os logs, sem publicar a senha SMTP.
  6. Não há giro? É preciso estar autenticado e possuir uma rodada pendente criada pela regra do sistema.
  7. O duplo clique abriu uma versão antiga? Confira o caminho do arquivo e inicie versoes/0.0.2/mvp-tattoo/app.py; os launchers da raiz e da 0.0.11 são históricos.

Ao reproduzir um problema, registre a rota, o status HTTP e os logs correspondentes. Evite corrigir dados diretamente no banco antes de identificar a regra que os produziu.
